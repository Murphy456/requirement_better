# A09 变更影响 · 参考样件与讲评

使用 v0.1 教学样稿。CR-01 在 L09.02 发放，由学员先作答，再对照[案例变更材料](../03_贯穿案例/04_变更与效果验证.md)及本页第二课。

## 第一课 · 顺着和倒着追

| 关系 | 样件 |
|---|---|
| 从目标正查 | GOAL-01 要减少核对准备负担。E01 和 E02 提供现行做法，E03 限定授权。DEC-01 给出首版选择，BR-02、BR-03 细化筛选，REQ-01 规定行为，AC-01 用 E05 验证当前结果 |
| 从场景倒查 | AC-06 检查下载前撤权，验证 REQ-03 和 BR-01，往上回到 E03 |
| 由共享规则扩大检查 | REQ-03 的三阶段检查还关联 AC-05 无权申请、AC-09 生成中撤权与 AC-01 正常成功。AC-01 也验证 REQ-01 的筛选 |
| 缺口 | 找不到「自动发送报表」的证据或决定时保留待查。请需求负责人核对记录或从候选范围移除 |

关联应有版次或出处。目标到场景的路径保留关系含义，验收成功证明特定行为，在 M10 再取业务效果证据。

## 第二课 · CR-01 差异与回归

| 影响 | 确定变化 | 待核问题及责任 |
|---|---|---|
| 范围与状态 | 从准备核对材料延伸到写台账和自动标记结算 | 财务及业务负责人确认结算规则、谁能决定、与关闭和重开是否独立 |
| 数据与权限 | 由授权读出增加跨系统写入 | 台账与信息管理角色确认写入主体、可写对象、字段映射及审核要求 |
| 接口与质量 | 要处理重复触发、部分失败、恢复和审计 | 交付评估一致性、恢复和可追查性，财务确认各异常的可接受结果 |
| 计划及验证 | 既有范围和新行为需区分 | 拟写入时，另列权限不足、重复请求、单边成功后恢复和重开场景。交付与测试根据依赖选择旧场景回归 |

可先维持 DEC-01 并单独调研，代价是近期没有自动回写；也可先验证证据充分的子范围，补齐结算及写入责任后再决定是否实施。示例建议暂缓批准写入，业务负责人会同相关角色确认所需记录、规则和代价后复议。

如果改动共用授权，回查 AC-05、AC-06、AC-09 及 AC-01。影响状态或时点去看 AC-07；影响重试或记录去看 AC-08。新写入的验收与旧导出的回归分别列明。仅同意调研时保留原需求范围，也不把原场景记成已复测。

## 第三课 · 版本、状态与决定

| 状态 | 责任及证据 |
|---|---|
| 候选 | 提出者记录需求和来源，需求负责人登记 |
| 已确认 | 业务负责人据情境、规则与范围决定并记录适用版本 |
| 已排期 | 交付负责人核对资源、依赖和风险后记录计划 |
| 已交付 | 交付团队给出交付版本及条目关系 |
| 已验证 | 测试或业务代表给出对应版本、场景及结果，明确验证的是行为还是效果 |
| 已撤回 | 有权限的决定角色记录原因、影响与替代项，保留原记录 |

v0.1 教学样稿可用于走读，真实试点待核查授权来源、质量条件和保留期限。CR-01 候选，允许开展调研。后续批准范围变化时，保留旧版本，建立新版本及批准记录，附重新验证的条目和场景。例外的临时暂停也注明角色、条件和恢复依据。

供讲评的两条记录：

| 对象 | 当前处理 | 责任、依据与后续 |
|---|---|---|
| v0.1 的 DEC-01 | 保留原范围与试点暂缓条件 | 业务负责人引用 A08 评审，现阶段可继续课堂走读 |
| 「每日自动发送报表」候选 | 假设撤回 | 假定业务负责人经查无使用安排，决定撤回。保留原条目、决定记录及影响说明。若收到可核查的新需要再提候选 |

撤回行是课堂补充示例。CR-01 仍处于候选，允许调研。

按 [R7](02_评分量规.md) 讲评。让学员指出每项影响是由哪条关系得出、需要什么证据才能恢复或改变决定。课中能提出暂缓且有充分理由即可得相应能力分。
