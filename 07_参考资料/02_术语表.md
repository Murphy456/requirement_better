# 课程术语表

以下是工作用解释，帮助读者统一讨论对象。不是标准全文译文，也不要求不同组织使用完全相同的中文名称。概念校准见[来源登记](01_来源登记.md)中的SRC-01、SRC-02、SRC-08。

| 术语 | 本课程中的用法 | 容易混淆的地方 |
|---|---|---|
| 需要 | 特定情境中希望得到满足的状态或条件 | 不一定已经说出口，也不必都是抱怨 |
| 诉求 | 某个角色提出的表达 | 是分析输入，不自动等于已确认要求 |
| 需求 | 对需要、能力或条件的可用表达 | 不限于功能清单 |
| 业务需求 | 说明改变要达到的目标与结果 | 目标指标不是已观察到的收益 |
| 干系人需求 | 与相关角色有关、连接目标与方案的需要 | 不只包括最终操作用户 |
| 解决方案需求 | 对解决方案能力和质量的要求 | 包括功能与非功能方面 |
| 过渡需求 | 从现状转到未来所需的临时条件或能力 | 不一定是长期运行功能 |
| 设计 | 对可能解决方案的表达 | 与需求可迭代细化，不应绝对割裂 |
| 需求开发 | 本课对获取、分析、表达、确认协商的教学分组 | 不等于程序开发；不是唯一行业分类 |
| 需求管理 | 维护状态、版本、追踪与变更等 | 与需求开发并行发生 |
| 业务规则 | 对业务行为施加条件或约束的约定 | 规则来源应核实，不能默认都是法律 |
| 假设 | 当前用于推理、仍需验证的判断 | 不能靠写入文档变成事实 |
| 表达检查 | 检查要求是否清楚、一致、达到质量要求 | 对应verification语境时应明确对象 |
| 需要确认 | 检查要求或产物是否适合相关需要 | 对应validation语境；不只是一句同意 |
| 实现验收 | 检查交付是否满足约定的接受条件 | 不等于业务价值已实现 |
| 验收条件 | 用于判断是否接受的明确标准 | 不限于正常操作路径 |
| 基线 | 作为共同参照、按约定控制变化的版本 | 允许按流程改变 |
| 追踪 | 记录需求与来源、决定及后续产物的关系 | 不是仅有文件目录 |
| 范围 | 当前变化和交付所覆盖的边界 | 范围外也要解释依赖与后果 |
| 质量要求 | 在规定条件下需达到的质量属性 | 精确数字不一定有依据 |
| 快照 | 在确定时点观察到的数据集合 | 不自动等于不可变业务账本 |
| 阶段门 | 本课用于检查成果能否支撑下一阶段的条件 | 是教学设计，不是外部认证规范 |

编号约定：C能力，M模块，L课时，K知识，A学习成果，R评分维度，T模板；案例内部使用E、H、BR、DEC、REQ、AC、CR，避免与课程结构混淆。
