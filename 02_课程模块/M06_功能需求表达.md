# M06 功能需求表达

对应能力 C06 与成果 A06。承接 A04、A05，将核对准备范围写成可实现、可验收的条目。三课各 25 分钟。用同一模拟案例演练，教学规则和真实批准分开记录。

课前准备 [学员页](../04_练习与评价/A06_功能需求包_学员页.md) 和 [参考样件](../04_练习与评价/A06_功能需求包_参考样件.md)，先发作答区，再出示当节示例。方法见 [核心知识](../01_知识体系/K06_功能需求表达.md)、[工作模板](../05_工作模板/T05_需求条目.md)，概念出处见 [SRC-01、SRC-02](../07_参考资料/01_来源登记.md)。

## L06.01 选择合适的表达粒度

能为目标、交互、组合条件和义务选表达，并说明使用者。 [完整讲稿](../10_完整讲稿/M06/L06.01_选择合适的表达粒度.md)

| 时间 | 活动与产出 |
|---|---|
| 00–03 | 出示导出目的，让业务、开发和测试各追问一个信息。 |
| 03–13 | 依次比较故事、用例、规则表和规格，示范权限三阶段及月份规则引用。 |
| 13–20 | 为三项内容选主表达，补一条可追踪规格骨架并互查。 |
| 20–25 | 收表达选择、使用理由和规格骨架。用「正确导出」练补规则和结果。 |

同一规则放在一处维护。可独立变化和验收的义务用条目表达。

## L06.02 把正常路径和异常写清楚

能写出触发、前置、结果和失败处理，保留未确认的重复提交行为。 [完整讲稿](../10_完整讲稿/M06/L06.02_把正常路径和异常写清楚.md)

| 时间 | 活动与产出 |
|---|---|
| 00–03 | 比较无匹配和生成失败时经办该做什么。 |
| 03–13 | 按 E05 模拟正常输出，演算空结果、撤权、任务失败和重试。 |
| 13–20 | 为正常及三个分支写条件、结果与下一步，互查缺号和异常。 |
| 20–25 | 汇报重试与旧快照的关系，课后补齐功能条目。 |

重试新建申请。连点提交没有已批准口径，应标待确认。

## L06.03 让需求能被共同评审

能用编号、版次、来源、理由、状态及责任支撑盲读，登记歧义。 [完整讲稿](../10_完整讲稿/M06/L06.03_让需求能被共同评审.md)

| 时间 | 活动与产出 |
|---|---|
| 00–03 | 让两人分别解释「十月工单」。 |
| 03–13 | 补追踪信息，演示零匹配、下载前撤权、失败重试三题，示范问题记录。 |
| 13–20 | 只按稿件预测三题，找缺口、处理责任和复核路径。 |
| 20–25 | 收实际修改、待确认项和版次。 |

已能回指规则的可直接修文档；业务预期缺项须由责任角色确认。

## 阶段提交与反馈

提交四条首版需求，保留条目编号、来源、目的、正常与异常、责任、状态、待确认和验收入口。A06 交给 M07 补质量与依赖，并交 M08 写验收和评审。 评价锚点见 [R5](../04_练习与评价/02_评分量规.md)。
