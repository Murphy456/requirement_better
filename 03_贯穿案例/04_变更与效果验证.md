# CASE-01 变更与效果验证

全部为教学设计；未发生真实上线，也没有实际效果数据。

## CR-01 变更注入

业务负责人提出：“既然都导出了，顺手把处理结果回写资产台账，再自动标记已结算吧。”

这引入跨系统写操作与结算状态，超出DEC-01。它不是已批准变更。首先要问：哪些记录可结算、谁负责确认、失败如何恢复、是否允许重复回写、重开工单如何处理、历史记录如何解释。

| 影响对象 | 需要重新确认的内容 | 处理建议 |
|---|---|---|
| 目标与范围 | 从核对准备扩展到结算处理 | 重新说明价值与风险，不沿用旧范围批准 |
| 状态与规则 | 工单关闭和财务结算是否独立 | 增加结算模型，不把已关闭直接等同已结算 |
| 数据与接口 | 资产台账写入权限、字段映射、失败处理 | 确认接口责任、重复请求处理与对账机制 |
| 质量与运行 | 并发写入、一致性、恢复、审计 | 交付团队评估可行方案，业务确认可接受损失 |
| 需求与测试 | REQ-01—REQ-04仍是导出范围 | 新增需求编号并回归旧权限、快照和重试场景 |
| 计划 | 新依赖和未知增多 | 先调研；可以维持原首版，另立变更任务 |

合理答案可以是接受、分期、拒绝或暂停，但必须说明决定者、证据、代价和复议条件。不能因为任务紧就不分析，也不能因为存在风险就永远不做。

## GOAL-01效果验证计划

| 层级 | 指标及口径 | 数据取得与限制 |
|---|---|---|
| 功能 | 按AC场景验证授权、字段、边界与失败 | 测试通过只说明已检查场景符合要求 |
| 使用 | 试点经办在真实核对准备任务中使用导出的情况 | 记录任务次数与使用次数；不用也要了解原因 |
| 过程 | 从开始整理至材料可核对的主动操作时间；等待时间另记 | 先记录现状，再按相近任务观察；不得从E02补造基线 |
| 结果 | 因字段缺失、口径不一致而返工的任务数 / 被观察任务总数 | 分类规则先定义；业务量和复杂度变化会影响结果 |
| 护栏 | 越权暴露、错误月份归属及误当结算凭证的事件 | 发生严重问题即暂停并复核，不能被平均收益抵消 |

试点先选一个园区的一类核对任务，记录任务复杂度与人员经验；观察前后变化并保留例外。若同时做数据清理与培训，就不能把改善全部归给导出按钮。初期小样本用于发现问题，未必支持稳定的总体估计。

接受阈值、观察周期与基线值在真实项目中均需协商。本教学参考刻意保留未知，学员应提出取得办法，而不是为了完成作业编造数值。

## 结果如何改变下一步

若复制时间减少但返工不变，检查数据质量与口径；若没人使用，调查工作流程、权限和替代工具；若使用增加但业务效果不明，完善测量而不是宣布成功；若出现越权则优先处理权限问题。每轮结论登记支持证据、局限与下一步决定。
