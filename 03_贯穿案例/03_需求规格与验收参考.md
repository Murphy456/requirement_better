# CASE-01 需求规格与验收参考

状态：教学参考基线v0.1；不是现实批准记录。规则以[业务模型](02_分析与建模参考.md)为准。申请、生成、下载采用同一申请ID；快照在申请被接受时确定。实现方法由交付团队设计，但对外行为要满足以下约定。

## 需求条目

| ID | 需求与可观察行为 | 依据 | 验收 |
|---|---|---|---|
| REQ-01 | 获授权财务经办选择月份和授权范围内园区；系统按BR-02、BR-03生成申请时点一致的业务快照；记录月份、园区与snapshot_at | DEC-01、BR-01—BR-04 | AC-01、AC-03、AC-07 |
| REQ-02 | 输出无宏XLSX，含下述字段；无匹配记录时仍输出表头及0条记录说明；资产缺失按BR-05表达；标识字段作为文本保留前导零 | E01、E05、BR-05 | AC-02、AC-04 |
| REQ-03 | 申请、生成、下载时检查权限；任一环节权限不足则终止或拒绝相应动作；不得下载已越权文件；提示重新选择范围申请 | E03、BR-01 | AC-05、AC-06 |
| REQ-04 | 明示文件是业务快照而非不可变月度结算记录；成功或失败均有可见状态；失败提供申请ID与可操作说明；重试建立新申请和新快照，不改写旧记录 | E06、BR-03 | AC-07、AC-08 |

## 字段字典

| 字段 | 含义与来源 | 空值与处理 |
|---|---|---|
| ticket_id | 工单唯一标识，工单系统 | 不允许缺失；缺失属数据异常，不能生成成功结果 |
| site_id | 所属园区，工单系统 | 必填，参与授权过滤 |
| asset_code | 资产编号，工单记录中的资产引用 | 可空；不得自行按名称猜测匹配 |
| current_status | 申请快照时的业务状态 | 导出行按规则均为已关闭 |
| latest_closed_at | 当前最近一次关闭时间，工单系统 | 导出行必有；按Asia/Shanghai表示 |
| issue_category | 故障分类，工单系统枚举 | 未分类显示“未分类”，不自行推断 |
| snapshot_at | 本申请快照时刻 | 全文件一致，含时区 |
| quality_flags | 数据检查标记 | 无问题为空；缺资产为missing_asset |

不包含联系人姓名、电话。选月、选园区、快照说明放文件说明页，不新增未经协商的个人信息字段。

## 验收场景

| ID | 前提 Given | 事件 When | 结果 Then |
|---|---|---|---|
| AC-01 | 经办仅有A园区权限；E05为快照数据 | 申请A园区10月导出 | 结果含WO-101、WO-102、WO-105，不含B园区WO-103及未关闭WO-104 |
| AC-02 | WO-102缺少资产编号 | 打开成功文件 | asset_code为空，quality_flags为missing_asset，不填0或猜测值 |
| AC-03 | 关闭时间分别为10月1日00:00与11月1日00:00 | 申请10月导出 | 前者包含，后者不包含；均按+08:00判断 |
| AC-04 | 当前范围与月份没有匹配工单 | 申请并完成导出 | 文件有表头，说明0条；不显示系统故障 |
| AC-05 | 经办只获A园区权限 | 尝试申请B园区数据 | 申请被拒绝，不产生B园区可下载内容 |
| AC-06 | A园区文件已生成，经办随后被撤销A权限 | 请求下载旧文件 | 拒绝下载整个文件，说明授权变化并提示重新申请 |
| AC-07 | WO-106在11月3日仍为处理中 | 此时申请10月导出 | 不包含WO-106；页面与文件均说明快照时间及非月度结算用途 |
| AC-08 | 一次生成任务失败 | 查看状态后重试 | 旧任务保留失败状态和ID；新建申请有新ID与快照，不显示旧任务成功 |

补充评审：生成期间撤权也必须阻断生成；这由REQ-03覆盖，课堂应补写对应场景，不能只依赖下载测试。

## 候选质量与运行要求

以下数字全部为教学协商示例，不是技术实测，也不是通用标准。

- Q-01：在约定测试环境、单申请不超过10,000行、10个同时申请的负载下，从申请接受至结果可下载，至少95%的有效申请不超过30秒。测试样本为100次有效申请，报告完整分布、失败率和环境；失败不能被删除来美化性能。此目标须经业务确认和技术可行性验证。
- Q-02：输出不得包含所选快照与授权范围外的数据。用越权申请、生成中撤权、下载前撤权和字段检查验证。这里的“全部通过”是样例测试结果要求，不是对所有可能攻击的数学证明。
- Q-03：记录申请ID、申请者标识、范围、快照时间、行数与结果，便于核查；不在日志复制导出数据。日志与文件保留期限由业务及信息管理角色在试点前确定，[待确认]，不得默认永久保存。

Q-01与Q-03当前有未决内容，生产项目不能直接宣称G3已经通过。本案例允许学员发现这些阻断项并提出协商办法。

## 上线依赖

先确认园区授权来源、状态历史与当前字段的关系、资产缺失处理责任、质量测试环境、文件与日志保留期限。试点前进行授权检查与样本核对；出现范围外数据时停止试点并处理权限问题。恢复现有人工流程时保留已生成记录的处理说明，不静默丢弃材料。
