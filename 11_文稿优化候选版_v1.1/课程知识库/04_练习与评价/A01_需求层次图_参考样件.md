# A01 需求层次图 · 参考样件与讲评

供讲师在学员作答后展示。示例体现一种可说明的判断。学员也可以选择别的候选方案，前提是写清依据和适用条件。

## 第一课 · 保留原话与修订

| 项目 | 样件 | 出处或状态 |
|---|---|---|
| 原始诉求 | 月底想导出 Excel，目前跨页面复制后再找资产编号 | E01，角色陈述 |
| 候选业务目标 | 减少准备月度核对材料的手工整理与返工 | 根据 E01 提出，待业务负责人确认，实际基线未测 |
| 角色需要 | 财务经办在月度核对前取得可与资产台账逐条核对的工单材料 | 根据 E01 提出，文件下游用途、匹配字段待经办确认 |
| 候选能力 | 按所选月份和授权范围取得核对材料 | 候选，月份口径待确认。Excel 是否必须要核对接收方工作 |
| 约束 | 经办只能取得当前授权园区内的数据。联系人姓名和电话不在本次核对字段中。权限变化须影响下载 | E03，模拟组织规则 |
| 待确认 | 缺资产编号时由谁核实，从哪份台账取得编号 | 向财务经办与台账责任人了解最近一次缺失的处理过程 |

修改记录可以写「原先写了导出全部园区。E03 说明授权范围有明确限制，改成只提供当前获授权园区内的数据。」

## 第二课 · 写出关联及其限度

| 关联 | 为什么有关 | 还缺什么 |
|---|---|---|
| 减少核对准备返工 → 经办能取得可核对的材料 | 材料可直接使用时，经办可能少复制和补查 | 用一次实际任务确认返工发生在哪一步，再决定怎么观察改善 |
| 经办能取得可核对的材料 → 系统能按月份和当前授权园区提供工单数据 | 系统能力覆盖取得原始材料的一步。E03 给出访问边界 | 核对所需字段、月份口径及缺编号处理仍需确认 |

过渡需求示例为有条件的「若首期核对依赖尚未映射的历史资产编号，切换前由台账责任人完成首期范围的映射，并按约定样本核对后结束过渡活动」。E01、E03 没有证明存在历史映射任务。写「待确认，需要检查首期是否依赖历史记录」也成立。

## 第三课 · 写出一条能被推翻的决定

- 当前暂选 A。按需生成可先覆盖经办自行决定何时取数的候选场景。取数是否常有临时变化，尚无记录。
- 如果经办和业务负责人确认几次核对都在固定时间集中取数，且月份与范围有统一口径，就重新评估 B。先请财务经办展示最近几次的取数、交接材料，核对是否符合这两个条件。
- 验收例子。经办失去某园区权限后，再下载之前生成的该园区文件，系统应不提供该文件。对应 E03。
- 效果观察。记录经办完成相同类型核对准备任务的实际步骤，比较是否少做了复制和补查。先取得现状记录，再谈改善程度。

暂选 B 的合理答案应同样写出它所依赖的固定时点与统一口径，并说明经常临时改范围会如何改变决定。暂缓的合理答案应给出要补的材料及负责角色，能说明拿到不同答案后采取的行动。

## 常见答案怎么反馈

| 学员写法 | 讲师可以这样反馈 |
|---|---|
| 财务每月都要导出所有工单 | E01 只有一个人的说法。E03 还限制园区范围。请改写涉及「都」「所有」的两处 |
| 需求是提高效率 | 写出哪个角色、哪段工作、预期少做哪一步，然后说明现状怎么查 |
| 业务需要 → 开发 Excel 按钮 | 在箭头中间补上经办用数据做的事。说明外部接收流程是否限定格式 |
| 旧工单全部迁移 | 先查首期核对要用哪些历史记录。将迁移写成有触发条件的候选过渡需求 |
| 选定时方案，因为肯定更省事 | 所谓省事指哪一步？什么新材料会让你改选按需生成？ |
| 能下载就说明减少了返工 | 把系统验收和经办实际工作各写一项检查，并注明所需证据 |

按 [R1 通用量规](02_评分量规.md) 做形成性反馈。仅复述一个功能且未明确角色或边界，对应明显不足。角色、情境、候选目标、数据边界和关联清楚，达到本模块基本要求。还能说明关联为何成立，并能依据新信息修订判断，是更稳健的表现。完整写出效益测量口径属于后续模块，本课检查学员是否已经明确要观察哪项工作结果。
