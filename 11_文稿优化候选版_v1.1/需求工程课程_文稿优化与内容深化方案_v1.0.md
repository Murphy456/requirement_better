# 需求工程课程文稿优化方案
## 从能照着讲，到愿意听、跟得上、用得出

版本：v1.0｜日期：2026-11-18  
适用项目：Murphy456/requirement_better  
本轮交付：文稿诊断、后续方向、实施批次与验收办法。正式讲稿与课件的批量修改按本方案后续推进。

## 1. 这段时间先推进什么

当前建议把课程工作重心调整为**文稿编辑与教学内容深化**。实际试讲暂缓，先完成能够通过案头工作改善的部分：把案例讲顺，把判断过程展开，把解释、观察、作答和回顾的节奏拉开。

希望形成的听课体验是：一个有判断力、愿意解释的人，带着学员看一件具体的工作怎样逐步变清楚。讲师可以有立场，也能说清自己为什么这样判断、什么信息出现后会改主意。学员有时间先想一步，再看讲师怎么处理。

这次优化同时抓三件事：

- **呼吸感**：同一段里有重点和次重点，有解释，也有读材料、想一想、改一句的空间。停顿期间，学员知道自己要做什么。
- **真人感**：讲师回应一个人实际会有的疑惑，角色有各自的任务和顾虑，选择有代价。幽默来自熟悉的工作处境，个人经历只使用你确认过的材料。
- **专业深度**：保留事实、假设和决定的区别，把方法如何帮助做决定、何时需要换方法讲透。

现有十模块、三十课及 A01–A10 成果链继续作为设计基础。25 分钟暂作单课预算，具体分段可以调整。实际用时与学习效果仍留待后续真人验证。

## 3. 后续优化方向

优先级：P0 为改写前应处理的基础问题；P1 为本轮主要投入；P2 为样板成熟后补充的内容；P3 为有时间接触真人时验证。

| 优先级 | 方向 | 具体怎么做 | 完成后怎么看 |
|---|---|---|---|
| P0 | 1. 统一主讲案例 | 招聘助手作为默认主讲线；把 27 节替换说明落实到正文、练习、讲评与转场。工单保留为明确标识的对照或迁移材料 | 沿一节课读下去，不需要临时把财务、工单换成 HR、简历 |
| P0 | 2. 对齐材料、编号与版本 | 建案例标识映射；核对 R-E、E、A 编号及投放顺序；同步讲稿状态和追踪记录 | 每个提问都能找到当时已经给学员的材料 |
| P1 | 3. 建立稳定的讲师声音 | 写一页表达约定：平实、直接、专业克制；用具体动作解释术语，允许适度幽默；保留个人偏好和判断理由 | 同一课里像一个人在连续说话，删去小标题也能接得上 |
| P1 | 4. 调整信息密度 | 给每节课圈出主判断；把辅助定义、长枚举和少用的例外转入讲师备注或课后阅读 | 学员每完成一小步，都知道刚才解决了什么 |
| P1 | 5. 设计有任务的停顿 | 在关键处写“先找两行”“预测结果”“改一个词”，再揭示解释；操作提示说明等待什么 | 停顿可执行，答案未在提问前泄露 |
| P1 | 6. 按课型改变讲法 | 概念课用一个反常识处境展开；访谈课沿回答追问；模型课边画边试错；决策课比较有条件成立的方案 | 相邻三课的主要学习动作有变化 |
| P1 | 7. 展开判断过程 | 保留初判、依据、新材料和修订位置；在适合的课中呈现一个合理但不完整的选择 | 学员能指出“哪条信息让我改了哪一句” |
| P1 | 8. 写出角色处境 | 为 HR、用人经理、开发、测试补充任务、顾虑、信息边界；新增情境明确标为教学模拟 | 同一个分歧可以从两方立场解释，角色不会只为配合正确答案发言 |
| P1 | 9. 增强对话的回应性 | 提问后预设几种回答去向：笼统回答、记不清、意见不同；下一句针对刚才的回答 | 去掉上一句回答后，能看出下一句追问失去了依据 |
| P1 | 10. 增加取舍和代价 | 比较手动选入、辅助比对、自动收集分别省哪一步、留下什么工作，写清决定的成立条件 | 参考答案容纳有依据的不同方案，同时指出不可越过的约束 |
| P1 | 11. 让课与课真正接力 | 开头取回上次成果中的一个未决问题，结尾把本次改动交给下一课使用 | 学员能说出这次为什么继续改同一份成果 |
| P2 | 12. 把理论放回判断现场 | 从已有方法选择和知识条目中选必要解释；交代方法解决什么问题、边界在哪里，再给名称和来源 | 学员能解释为什么用这个方法，也知道何时不用 |
| P2 | 13. 补充不完美作品与讲评 | 为重点能力准备“可接受但不完整”“形式漂亮却判断有误”的匿名教学样件 | 讲评能指出具体改哪一处及原因，不只宣布标准答案 |
| P2 | 14. 增加现实工作难题 | 逐步加入需求人没空、材料不全、口径变化、会议时间不足等场景；从现有事实推演，新增部分标模拟 | 学员能在条件不齐时写出下一步，而非等待所有信息齐备 |
| P2 | 15. 丰富迁移与成果体验 | 主案例之外，用会议室、制度问答等短题检验方法选择；展示成果初稿和修订稿的差异 | 学员能说出换业务后哪些判断保留、哪些规则必须重建 |
| P2 | 16. 调整 HTML 的揭示节奏 | 随定稿检查问题、线索、答案的出现时机；逐页对应讲稿版本；必要解释放备注 | 页面支持思考过程，学员不会先看到结论再被要求独立判断 |
| P3 | 17. 用少量真人反馈校准 | 日后只测仍有疑问的片段，再恢复完整试讲；保留作品、用时与误解记录 | 能区分“编辑认为顺畅”和“学员确实跟得上” |

这里不要求每节课同时拥有故事、冲突、笑点、反转和反例。先判断哪种活动能帮助这一课的学习，再决定保留什么，避免形成新的固定套路。

## 4. 十个模块分别往哪里做深

下表为后续内容设计建议，新增角色压力、对话和结果均须在制作时注明来源或模拟性质。

| 模块 | 优先深化的内容 | 适合的讲述方式 | 学员应感到的进展 |
|---|---|---|---|
| M01 需求本质与层次 | 为什么听见“自动刷”就想查接口；系统能力与工作目标之间缺了哪一环 | 保留第一反应，逐句辨认，再用新规则修订 | 我开始知道哪些是对方说的，哪些是自己补的 |
| M02 目标范围与干系人 | 谁能说明问题、谁能作决定、谁承担新增工作；资源有限时先查什么 | 多角色各讲一句，再决定找谁核实 | 我能把“大家都觉得需要”变成一项可调查的问题 |
| M03 获取证据与不确定性 | 受访者答得笼统、记不清、不同材料来自同一来源时怎么办 | 分支访谈、两种问法对照、台账修订 | 我会沿回答继续问，也会收住超出证据的结论 |
| M04 业务建模与规则 | “已筛完”“待复核”“读取失败”分别意味着什么；JD 变更如何影响结果 | 跟着一份简历走流程，遇到例外再补图 | 我画的图能解释一次实际操作 |
| M05 方案比较与优先级 | 同一目标的多种实现；人力节省、依赖与残留工作怎样一起比较 | 两个有理由的提案交锋，给新条件后重排 | 我能作暂时有依据的选择，也知道何时重议 |
| M06 功能需求表达 | 业务、开发、测试为什么会从同一句话读出不同要求 | 盲读、复述、定位歧义、现场改一句 | 文稿开始能被别人独立使用 |
| M07 质量数据与过渡 | 系统响应快、理由正确、HR 省时是哪些不同问题；上线前哪些工作要先完成 | 两种计时方法、两份统计报告、一次切换推演 | 我能把形容词写成别人测得出来的条件 |
| M08 需求确认与验收 | “整体通过”到底准许什么；有分歧和未决项时怎样结束会议 | 一段短评审，先暴露分歧，再形成带条件的决定 | 我能组织一次留下明确结论的讨论 |
| M09 追踪基线与变更 | “只改一句 JD”如何影响理由、历史结果与验收 | 沿同一条结果追查，把新旧版本并排比较 | 我能解释一个小改动为什么影响多处 |
| M10 效果评价与迁移 | 功能有输出、有人使用、工作改善如何分别判断；换业务后如何裁剪方法 | 对照观察计划、陌生短案例、交付答辩 | 我能说明成果有什么用，以及目前还不能证明什么 |

深化原则：优先补“为什么这样判断”和“条件变了怎么办”。已有课程骨架足以承载这些内容，暂不以新增模块数作为进展。

## 5. 呼吸感与真人感怎样落到文字上

### 5.1 四种可直接使用的编辑动作

**把一个长解释拆成几次观察。** 例如先让学员找到空白行，再说我们数到了什么，最后讨论能不能推断候选人没有经验。每一小步都推进同一个问题。

**让过渡有前因。** “接下来学习状态模型”可以改成：“刚才这份简历没出现在结果里。是还没处理、读取失败，还是证据不足？先把这几种情况分开。”下一段因此有了具体任务。

**对合理的第一反应多解释一步。** 学员想做自动化，是因为听到了反复操作。讲稿先说明这个反应从哪里来，再讨论还缺什么信息，避免一直用纠错的口吻推进。

**给轻松的句子留位置。** 例如讲需求文档时可以说：“你人还在会议室，大家都能听懂。你一离开，这句话就开始有三个版本了。”这种句子服务于歧义问题；如果一段已经清楚，就不必硬加笑点。

### 5.2 一段具体改写示范

以下是 L03.02 的编辑示意，沿用 R-E05 的教学模拟材料，不是已完成验证的正式改稿。

**当前表达节选**

> 两行证据栏空白，五行进入统计，算出来是 2/5。我们数的是记录里的空格。候选人会不会做数据核验，还要看原简历、面试证据或其他可核查材料。

**拟调整的讲述**

> 先别看那句“40% 的人没有经验”。只看表，帮我找出证据栏空着的两行。
>
> （等学员指出 CV-102、CV-104，再圈出来。）
>
> 对，两行。五行里有两行空白，40% 没算错。
>
> 现在把表收起来。如果你回去跟用人经理说：“这些候选人里，40% 没做过数据核验。”这句话比刚才多说了什么？
>
> （留出作答时间；没有回应时，把“记录没写”和“人没做过”并排展示。）
>
> 表里没记下来，可能是简历没写，也可能还没看完，或者摘录时漏了。现在可以确定的，是两格空白。要判断候选人做没做过，我们还得回到原材料。
>
> 先把这句话修到这里。还有“全公司”三个字，下一步再看这五行能不能代表它。

改动集中在三个地方：一次只处理一个推断；让学员先说差异；把另一项问题延后到下一步。概念和证据边界保持准确。

### 5.3 判断过程的示意

用于 L05.02 的候选口播，新增讨论属于教学推演：

> HR 想少翻几次简历，我们很容易先把“自动收集”放到前面。这个选择有它的理由。
>
> 但先把流程停在这里：假设简历已经收齐了，结果只写“匹配度高”，没有原文位置，HR 接下来会做什么？
>
> 她可能仍要一份份翻回去。那我们就得分别问：现在主要费时的是找简历，还是找到以后核对经历？
>
> 我暂时倾向于先把“手动选入、辅助比对、理由能回查”走通。这项判断要写上条件：它是否真的减少了回头找资料。如果后续观察表明负担主要在收集环节，排序就需要重议。

这段体现的是讲师的候选判断，不是你的真实项目经历。正式采用时，观点可以保留或调整，涉及真实经验的第一人称叙述另需你确认。

## 6. 制作批次与交付

不设强制开课日期，按成果推进。样板完成后再估算全课改写工时，避免把教学时长当成制作时长。

| 阶段 | 工作内容 | 具体交付 | 进入下一阶段的条件 |
|---|---|---|---|
| A：先把底稿理顺 | 建立 30 课问题清单；确定默认主讲案例；登记编号、材料投放和状态问题；写一页表达约定 | 逐课问题清单、案例与材料映射、表达约定 | 每课知道改什么、依据在哪、会影响哪些配套文件 |
| B：做三种改写样板 | L01.01 概念判断；L03.01 访谈对话；L05.02 决策取舍。同步相应练习、讲评和讲师提示 | 三份完整改稿、三段前后对照、各课待验证问题 | 案例连贯，讲法有差异，练习可独立完成，表达方向能够沿用 |
| C：按模块扩展 | 完成剩余 27 课，分批回查前后成果与依赖；重点补充必要的角色、反例和分支 | 30 课修订稿及受影响的配套材料、变更记录 | 内容、材料、讲评、版本对应；没有需要讲师临场补齐的关键缺口 |
| D：复核和整理展示 | 检查口播与课件揭示顺序；维护已有 HTML；形成将来只需重点验证的问题清单 | 文稿版本包、HTML 对应表、案头检查记录、真人验证清单 | 案头问题关闭，真人待验事项仍明确保留 |

阶段 C 建议按以下三批，兼顾相邻课的连读：

| 批次 | 内容 | 剩余课数 | 重点回查 |
|---|---|---:|---|
| C1 | M01–M03，扣除阶段 B 的 L01.01、L03.01 | 7 | 从诉求到调查问题再到证据，是否连续推进 |
| C2 | M04–M06，扣除阶段 B 的 L05.02 | 8 | 模型、方案与需求表达是否使用同一组规则 |
| C3 | M07–M10 | 12 | 质量、验收、变更和效果观察是否形成完整关系 |

原 S01、S02、S03 继续作为后续试讲入口。阶段 B 的三课用于校准不同讲法，不新增三场必须安排的试讲。L03.02 与 L07.01 在对应批次重点处理解释密度。

**你需要投入的部分可以集中在阶段 B。** 有空时看三段前后对照，标出“像我会说的”“太刻意”“专业判断不认同”的地方即可。不要求先通读三十课。若暂时没有反馈，可按已明确的“平实幽默、对话感、专业克制”继续形成候选稿；个人经验和真实项目事实留待确认。

## 7. 没时间试讲时，怎样检查进展

案头检查可以发现文字和材料问题，也有明确边界。所有检查记录都注明方法和对应稿件版本。

| 检查方式 | 现在可检查什么 | 仍需留给真人验证什么 |
|---|---|---|
| 连续阅读与口播编辑 | 句子拗口、指代不清、转场生硬、解释重复 | 学员的实际理解速度与疲劳 |
| 案头计时预算 | 给读材料、计算、作答、展示分配时间；检查总量是否明显不合理 | 实际课堂耗时；没有朗读就不记为“朗读通过” |
| AI 模拟不同答案 | 暴露任务指令歧义，寻找漏掉的回答分支 | 真实学员出现某种错误的比例、真实学习效果 |
| 按学员页独立做题 | 输入是否足够，能否找到出处，任务与讲评是否对齐 | 学员是否愿意完成、能否在规定时间内完成 |
| 相邻课连读 | 重复讲解、案例跳转、成果断档、前置知识缺失 | 连续学习时的兴趣与负担 |
| HTML 与讲稿对照 | 答案是否提前显示、页序是否支持讲述、备注是否与正文一致 | 实际投屏、操作与讲授是否配合顺畅 |
| 可选的异步片段反馈 | 日后找愿意帮忙的人，只读或听一个片段，复述听懂了什么 | 整门课效果与长期迁移 |

状态分开记录：**已改写、案头检查通过、口播待验、学员待验、展示待同步**。可以先作为追踪字段维护，与现有 production_status、trial_status 建立映射后再统一修改。

## 8. 本轮验收标准与停止条件

每个模块提交时检查以下事项：

1. **连续性**：正文、练习、讲评与下一课使用的案例一致；引用的材料已在需要之前发放。
2. **理解负担**：重点解释分步推进；长段有保留理由；补充说明有合适去处。
3. **判断过程**：关键选择写出依据、成立条件及可能改变结论的信息。
4. **回应性**：重要提问之后有等待任务和必要的应答分支；不会立即替学员答完。
5. **角色与经验**：人物行为有任务背景；模拟对话、教学假设、真实项目事实标识清楚。
6. **专业准确**：改写没有删掉关键限定，没有改变原数字的分母、范围与规则。
7. **成果与讲评**：学员产出能显示该课判断；讲评说明具体修改位置，也容纳有依据的不同答案。
8. **版本与展示**：改动能追到对应材料、参考答案和 HTML；未验证的项目没有标成已完成。

满足上述案头标准后，本轮即可收束。剩余问题集中交给未来的真人验证，不再无限进行风格润色。若连续两轮只在替换近义词、没有解决新的理解障碍，应暂停改写。

## 9. 配套材料怎样整理

沿用现有目录，正式讲稿保持单一维护入口，避免再生成一整套“优化版讲稿”与原稿并存。

| 位置 | 建议用途 |
|---|---|
| 08_项目维护 | 保存本方案、逐课问题清单、表达约定与检查记录 |
| 03_贯穿案例/招聘助手 | 维护角色说明、模拟材料、补充情境及其使用课时 |
| 10_完整讲稿/Mxx | 保存每课最终采用的正文、讲师提示与可选追问 |
| 04_练习与评价及招聘案例现有学员页 | 同步本次修改影响到的任务、样件与讲评 |
| 09_样课/HTML试讲材料 | 在讲稿稳定后更新展示，记录讲稿版本和揭示顺序 |

仓库中已有三节样课及全课程 HTML 文件，现有设计规范仍有“定稿后再制作”的措辞。后续应把这部分调整为已有课件的维护和复核流程，并逐课确认实际内容与新稿的对应关系。本轮只核对了文件清单及设计规范，未逐页验证全部 HTML。

如果将来补充真实经验，先用一张短记录即可：当时是什么场景、谁说了什么、最初怎么判断、后来哪条信息改变了判断、哪些内容可以公开。两三条有具体转折的经历，往往比大量泛泛的“项目经验”更适合用于文稿；也可以暂时全部使用明确标注的教学模拟。

## 10. 下一轮最先完成的工作

下一轮建议依次交付：

1. **30 课文稿问题清单**：每条定位到具体段落，写明现象、修改动作与配套影响。
2. **一页表达约定**：用本课程的句子说明保留什么、怎样改，保持简单可执行。
3. **L01.01、L03.01、L05.02 三课改写包**：含正文、必要配套修订、前后对照和待验证项。
4. **样板复核记录**：确认哪些编辑动作值得推广，随后进入剩余 27 课。

这四项均可在暂不试讲的条件下推进。后续恢复试讲时，用明确的问题清单去验证本轮留下的疑问。
