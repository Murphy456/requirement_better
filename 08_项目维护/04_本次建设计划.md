# 需求工程知识库建设计划

## 目标与依据

依据[课程总设计](../00_课程设计/01_课程总设计.md)，交付可阅读、可扩展、可据以生产课程的知识库，并推送用户指定的空仓库。技术形式为UTF-8 Markdown、标准相对链接与CSV索引；不建设网站，不添加运行时依赖。

用户已授权深化设计与推送；按通用业务课程处理行业未定问题。仓库当前公开，保持现有可见性。只写原创教学内容及明确标注的模拟材料，不携入私人写作样本或其他项目文件。

## 工作步骤与验收

- [x] 建立总设计、能力矩阵、课程地图与教学试点方案；核对课时计算和能力覆盖。
- [x] 编写10个模块、30节课的详细设计及10篇核心知识；每课必须有目标、判断、活动、成果与检查标准。
- [x] 建立主案例证据、模型、需求、验收与变更链；逐项核对角色、字段、状态与编号。
- [x] 配套阶段任务、评分量规、模板、AI辅助和三个样课；核对任务有输入、产出与评分依据。
- [x] 完成独立审阅、修订、内部链接和结构校验；区别教学设计完成与教学效果未验证。
- [x] 通过GitHub写入内容，回读分支、提交和文件树，记录发布结果。

## 复核重点

外部术语与课程自定义是否分开；来源是否实际核验；模拟数据是否误写成事实；验收条件是否遗漏权限与失败；考核分数与阶段门是否冲突；30节课的生产状态是否真实。

## 设计判断

1. 使用10模块而非最初8模块，将质量要求与变更管理单列，防止它们成为功能课的附注。
2. 保持单一主案例，但设置不同领域的结课任务，避免只会重复样例。
3. 提供3个完整样课教学稿，其余27课先交付详细设计；不虚称视频和全部逐字稿已完成。
4. GitHub与Obsidian共用相对链接，不要求安装插件。
